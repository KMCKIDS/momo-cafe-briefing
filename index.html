카페 돈의 대부분은 이미 어딘가에 전자 기록으로 남습니다. ‘수집 API’는 홈택스·카드사·은행 기록을 대신 가져다주는 유료 중개 서비스(코드에프·팝빌·바로빌 등)입니다.

기록끼리 잇는 규칙

  1. 자동 분류: 거래처 이름으로 항목을 정합니다. 사장님이 한 번 고치면 다음부터 기억합니다.
  2. 중복 제거: 체크카드로 산 우유는 카드 내역과 통장 출금에 두 번 잡힙니다. 한 건으로 묶습니다.
  3. 카드 입금 대사: 승인된 매출과 며칠 뒤 통장 입금을 맞춰 보고, 수수료가 약속보다 많거나 입금이 빠지면 알립니다.
  4. 증빙 구분: 세금계산서·카드·현금영수증은 자동으로 ‘증빙 있음’, 증빙 없는 현금 지출만 사진을 요청합니다.
  5. 면세 표시: 우유처럼 부가세가 없는 재료를 따로 표시해 세금 계산에 씁니다.

첫 실전은 2027년 1월 25일 부가세 신고입니다. 그 전에 1~3단계를 끝내고, 원가·재고·인건비는 그 뒤에 붙입니다. 기간은 제안입니다.

만들지 않을 것

  • 결제 기능: POS가 이미 합니다. 앱은 POS 기록을 받기만 합니다.
  • 세금 신고 제출: 제출은 세무사나 홈택스에서 합니다. 앱은 신고 숫자를 맞춰 넘깁니다.
  • 복식부기 회계: 세무사 프로그램의 일입니다. 사장님 장부는 들어온 돈·나간 돈·남은 돈이면 충분합니다.
  • 단골 쿠폰·마케팅: 장부가 자리 잡은 뒤에 따로 정합니다.

지인에게 먼저 확인할 질문

답에 따라 연결 순서와 비용이 달라집니다. 브리핑 자리에서 체크해 가며 쓰세요.

만드는 방식에 대한 메모

  • 지금 형태: 화면 모양으로 보아 Claude 아티팩트로 만든 앱입니다. 화면 설계와 손 입력까지는 이대로 충분합니다.
  • 서버가 필요한 이유: 밤마다 수집을 돌리고, 수집 API 열쇠와 홈택스 계정을 안전하게 보관하고, 장부를 백업해야 합니다. 아티팩트 안에서는 이 세 가지를 할 수 없습니다.
  • 보안: 홈택스 본 계정 대신 조회 전용 부서사용자 계정을 쓰고, 저장은 암호화, 직원은 매출·급여를 못 보게 합니다.
  • 비용: 수집 API 요금(건당 또는 월정액) + 서버비. 업체 2곳 이상 견적을 받아 비교합니다.
  • 이미 있는 서비스: 캐시노트 같은 앱이 카드·홈택스 수집을 이미 합니다. 우리 앱의 차별점은 마감 루틴, 원가·재고·인건비, 세무사 전달을 한 화면에 묶는 것입니다. 수집을 직접 만들지, 그런 서비스에서 받아올지는 비용을 보고 정합니다.

Claude로 우리 가게에 맞게 고치기

이 페이지 링크를 Claude에 주고 아래 문장을 상황에 맞게 바꿔 붙여 넣으세요.

이 페이지(링크)를 읽고 우리 가게 정보로 바꿔 줘. 과세유형: ○○, POS: ○○, 배달앱: ○○, 직원: ○명, 월 고정비: ○○원, 한 달 영업일: ○일. 바뀐 화면은 기존|새 비교표로 먼저 보여 주고, 내가 좋아요 한 것만 반영해 줘.
따라하기 탭에서 우리 가게에 해당 없는 걸음(예: 배달앱을 안 함)은 빼고, 이미 끝낸 걸음은 완료로 표시해 줘.
‘만드는 사람’ 탭의 0~2단계를 Claude Code로 실제로 만들어 줘. 데이터 원칙 네 가지와 단계별 통과 기준을 그대로 지키고, 비밀번호·키는 코드에 넣지 마.
이 페이지의 세금·노무 숫자(간이과세 기준, 카드 세액공제율, 최저시급, 원천세·부가세 기한)가 오늘도 맞는지 korean-law-search 스킬로 법령 원문을 다시 확인하고, 바뀐 게 있으면 고쳐 줘.
